drawingboard

A local design and task board that lives inside your project and is shared by you and Claude. You draw mockup screens, mark them up and keep tasks; Claude Code reads and edits the same files.

How it works

  1. You place a mark on an element: a comment pin, a box or an ellipse, an arrow, a strike, "move this there". It is saved as one file on the element's id, with status open.
  2. Claude hears what you changed with your next prompt or, through the plugin's monitor, while it is still working. It reads the open marks with drawingboard marks and the screen as a text outline with drawingboard show.
  3. Claude changes the screen with drawingboard patch. The canvas updates live.
  4. Claude replies on the mark and sets it to addressed. If it declines, wontfix needs a reply saying why.
  5. If you agree, you set it to Resolved. Claude never resolves your marks: the CLI refuses it.

The problem

Telling an agent what is wrong with a screen usually takes a screenshot and a paragraph about where to look. A screenshot is pixels. It does not say which element you meant, and it is out of date after the next change.

Review comments also need somewhere to live. In a chat they scroll away, and nobody can tell which ones were dealt with.

What it does

  • Mockup screens built from a catalog of typed placeholders for five platforms: macOS, Windows, iOS, Android and web. Architecture diagrams use the same canvas.
  • Marks: comment pins, boxes and ellipses, arrows, strikes, "move this there", text on the canvas and pen strokes. Each is one file with a status.
  • A watch for your marks: drawingboard marks --watch waits until you add or change a mark, prints it and exits. The plugin's monitor runs it, so a mark reaches a live session at once.
  • Layouts as hints: a stack, grid or flex tells Claude how the real app should behave, so it picks the framework's natural equivalent instead of guessing.
  • From mockup to code: drawingboard handoff prints a build brief for a screen, and drawingboard built records that it is built; show and status then say what changed since.
  • A task board where each column is a folder and each task is one file. Refs link a task to screens, elements, marks and other tasks.
  • A Claude terminal docked in the app: a real Claude Code session in your project. "Ask Claude" buttons type a precise reference into it and never press Enter.
  • Checkpoints: named snapshots of the board that you can diff and restore. In git they are refs of their own and never touch your branch.

The edge

  1. Marks are review data on mockups that exist before any code. Each has a kind, an element id, a snapshot, replies, and a lifecycle in which Claude may set addressed but never resolved.
  2. Typed native screens for macOS, Windows, iOS and Android, which a "click the running page" tool cannot reach.
  3. Claude hears only what you changed, with your next prompt or, through the plugin's monitor, while Claude is still working.
  4. Links from a mockup to the code that implements it, with drift in both directions.

How it compares

drawingboard is a narrow tool: for one developer who builds a native desktop or mobile app (or a web one) with Claude Code and wants to sketch the intent first and review it without screenshots. It works with Claude Code only. Other tools do neighbouring jobs, some of them better.

ToolWhat it does betterWhat drawingboard has that it lacks
Claude DesignGenerates the design itself, checks it against your brand, exports PDF, PPTX and HTML, and needs no install.It is cloud only and makes hi-fi web output. No catalog of native platforms; comments are not files in your repo.
AgentationWorks on the real, running UI: click an element, write a note. It has an acknowledged state and webhooks, which drawingboard has not.It needs a running React app and is desktop web only, so it does not reach a mockup or a native app.
PencilA real design canvas with variables and tokens, a two-way local MCP server, a headless CLI, and many agents.No lifecycle for review marks that could be found. It is centred on the web, and the app is closed.
Backlog.mdThe better task board: tasks as files in the repo, a CLI, MCP and a local web kanban, five agents.No mockups and no marks.

When not to use it

  • You want polished web designs made for you. Use Claude Design or Pencil; they go well beside it.
  • You want to point at a running web app. Agentation works on the real page.
  • You only want tasks as files. Backlog.md is the better task board.
  • You work in a team on one board. There are no accounts and no cloud, and you should not run the app on a machine you share.
  • You use another coding agent. It works with Claude Code only.

The plugin's monitor depends on Claude Code monitors, an experimental feature that does not start in -p runs. Where it is missing nothing is lost: the prompt notice reports the same marks with the next prompt.

How far this release is tested. The Go tests, the UI tests and the build pass on Linux, with an older Go than the project asks for. Nothing has been run on macOS or Windows. The plugin, its hooks and the marks monitor have not been tried in a live Claude Code session.

Compared on 2026-11-19 from each tool's public page. Other tools change; check before you choose.

Install

Not public yet. There is no public repository or release yet. These are the commands as they will be once there is one.

Install the binary first. Download it for your platform (macOS or Linux) from the releases, once one is published; the install script picks the right one, checks its checksum and puts it in ~/.local/bin:

curl -fsSL https://github.com/mr-wheelkers/drawingboard/releases/latest/download/install.sh | sh

Or build it from the repository with Go and Node. Node is only needed to build the UI; the binary embeds it.

make build       # bin/drawingboard
make install     # copies it to ~/.local/bin/drawingboard

Then either add the Claude Code plugin, which brings the skill, the hooks and the monitor to every project that has a drawingboard/ folder:

/plugin marketplace add mr-wheelkers/drawingboard
/plugin install drawingboard@drawingboard

or let drawingboard init write the skill and the hooks into one project. Use one or the other. The plugin does not contain the binary: its hooks, its skill and its monitor run drawingboard from your PATH.

Quick start

  1. In your project folder, run drawingboard init. It creates drawingboard/ with a sample screen, a sample mark and a sample task, and installs the skill, the CLAUDE.md section and the hooks.
  2. Start the app with drawingboard and open http://127.0.0.1:4320.
  3. Press M for mark mode, pick Comment pin (C) and click a button. Write what you want and save.
  4. Open the Claude terminal with Ctrl+`. In the Marks tab, click "Ask Claude to address open marks" and press Enter.
