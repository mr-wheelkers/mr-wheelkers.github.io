simq documentation

simq is a queue for iOS simulator tests. Any number of sessions (people, scripts, Claude Code agents) submit a test run; an always-on harness runs them one per simulator, with warm DerivedData, and hands back the result. It is being folded into daleq's iOS plugin, which reads the same .simq.toml.

Not public yet About simq Source on GitHub

Install

Not public yet. The repository is private today. These are the commands as they will be once it is public.

Needs Xcode (tested with 26.6) and at least one iOS simulator runtime.

As a Claude Code plugin:

/plugin marketplace add mr-wheelkers/simq
/plugin install simq@simq
/simq-setup

Or run the installer in a checkout of the repository:

scripts/install.sh                 # or: scripts/install.sh --workers 3 --model "iPhone 17" --runtime 26.5

This builds a release binary, copies it to ~/Library/Application Support/simq/bin/simq, links ~/.local/bin/simq, writes the launchd agents for the broker and the workers, starts them, and runs simq doctor. Run it again to update.

The first start takes a few minutes: the workers create simq-golden, boot it once (a new simulator's first boot runs a data migration), and clone simq-1…N from it.

simq uninstall [--delete-simulators] [--purge] removes it.

Quick start

simq submit --wait                                # all tests of the project in the current directory
simq submit ~/src/App --wait --kind unit          # unit test bundles only
simq submit --wait --only AppTests/ParserTests --only AppUITests/LoginTests/testLogin
simq submit --wait --shards 2                     # split by test class over 2 workers, one merged result
simq submit --wait --json                         # job + result as JSON
simq submit                                       # queue and print the id; later: simq wait ID

simq submit --wait from an iOS project builds if needed, tests, prints the result and exits with a code that says what happened.

Concepts

Broker

The broker (simq broker, launchd dev.simq.broker) owns the queue on disk, hands jobs out as leases, re-queues a job when its worker stops heart-beating, gives up after 3 attempts, and stores results. Clients only talk to the broker.

Workers

There is one worker per simulator (simq worker N). A worker claims a job, then:

  1. runs the project's generate hook (for example xcodegen) and xcodebuild build-for-testing into a DerivedData directory per project. This is skipped when the source fingerprint (git tree + dirty diff + untracked files, or file mtimes outside git), Xcode build and settings are unchanged since the last build;
  2. runs xcodebuild test-without-building -xctestrun … on its own simulator, with parallel testing off and per-test timeouts on, so a hanging test fails instead of hanging the run;
  3. reads xcresulttool get test-results summary into pass and fail counts, failing tests with messages, timings and artifact paths.

Self-healing

  • Wall-clock timeouts for build and tests; the whole xcodebuild process group is killed.
  • A run without results is retried once after rebooting the simulator.
  • Booting escalates: reboot, erase, then delete and re-clone from simq-golden.
  • A restarted worker kills what its previous self left running and re-sends an undelivered result. launchd restarts crashed daemons.

Golden simulator

A new simulator's first boot runs a data migration that can take minutes. simq boots simq-golden once and clones worker simulators from it; clones boot in well under a minute.

Why parallel testing is off

With xcodebuild's default, the small app's run cloned the destination three times and took 146s instead of 76s. Parallelism comes from the pool: one job per simulator, several simulators.

Sharding

With --shards N, the worker that claims the job builds it, lists its tests, and deals the test classes into N groups, slowest first onto the lightest group, using per-class durations recorded from earlier runs. Any worker takes the shards, and the parent's result is the merge: counts summed, failures concatenated, test time = the slowest shard.

Snapshot mode

DerivedData is per project path, so every new worktree of a repository would build cold. With snapshot = true, a job carries the commit plus a patch of the dirty tree, and the worker applies it in one simq-owned checkout per repository, shared by all worktrees.

One build at a time

Builds are serialised per project with a file lock: exclusive while building, shared while tests read the products, so two workers on one project build once.

Command reference

simq submit --wait                                # all tests of the project in the current directory
simq status [ID]                                  # workers, queue, recent results / one job
simq log ID [--build] [--follow]
simq cancel ID
simq prune [--days 7] [--derived-days 14] [--dry-run]   # the broker also does this every 6h
simq doctor [--fix]

Exit codes

Exit codes of submit --wait / wait: 0 passed, 1 tests failed, 2 build failed, 3 timeout, 4 infrastructure error, 5 cancelled, 64 usage.

Project settings: `.simq.toml`

Optional; looked up from the submit directory to the git root. Without it simq uses the single .xcworkspace/.xcodeproj in the directory and a scheme of the same name.

workdir = "ios"                    # where xcodebuild runs, relative to this file
project = "App.xcodeproj"          # or: workspace = "App.xcworkspace"
scheme = "App"
test_plan = "Fast"
generate = "xcodegen"              # run before a build (only when one is needed)
skip = ["AppUITests/SlowTests"]    # default skips, dropped when --only is given
device = "iPhone 17"
runtime = "26.5"
timeout = 1800                     # test run wall clock, seconds
build_timeout = 3600
test_timeout = 600                 # per test (XCTest rounds up to minutes)
shards = 2                         # split each run over up to 2 workers by test class

Pool settings

~/Library/Application Support/simq/config.json is written by the installer; simq config prints it. Keys: workers, model, runtime (null = newest), leaseSeconds (30), maxConcurrentBuilds (1), allowSimulatorServiceRestart (false), pruneResultDays (7), pruneDerivedDays (14), pruneIntervalHours (6), diskWarnGB (60). Restart the agents after editing: run scripts/install.sh again.

SIMQ_HOME moves everything (queue, DerivedData, artifacts, socket); SIMQ_SOCKET moves only the socket.

Claude Code integration

The repository is a Claude Code plugin and a one-plugin marketplace. The plugin gives sessions:

  • a skill: when and how to submit, and how to read results;
  • /simq-status;
  • /simq-setup: install, update, doctor, uninstall.

simq and daleq

daleq's iOS plugin is the tool that replaces simq. It reads the same .simq.toml, its simulators keep the simq- names, and it adds iPad and Apple Watch pools, leases for hands-on work and progress counts. See the daleq documentation.

Security and privacy

  • Only simq-* simulators are ever booted, erased, cloned or deleted.
  • Clients talk to the broker over a Unix socket on the same Mac. Multi-machine is not built.
  • Restarting CoreSimulatorService disturbs every simulator, so simq does it only if allowSimulatorServiceRestart is set. It is off by default.
  • In snapshot mode the patch of the dirty tree is built in a temporary index and object directory, so the submitter's repository is never written to.
  • State lives in ~/Library/Application Support/simq/: the queue, results, DerivedData and artifacts. simq prune removes old results and DerivedData, and the broker also does this every 6h.

Troubleshooting

SymptomWhat to do
The first run after install is slowThe first start takes a few minutes while the workers create and boot simq-golden.
Something is wrong with the poolsimq doctor [--fix].
A build failed (exit 2)Read the build log: simq log ID [--build] [--follow].
Exit 3A wall-clock timeout. Raise timeout, build_timeout or test_timeout in .simq.toml if the run is legitimately long.
Exit 4An infrastructure error, not a test failure. simq status [ID] shows the workers.
Every run rebuildsGenerated projects (generate) should be git-ignored, or regenerating them changes the fingerprint.
The disk is filling upsimq doctor warns above diskWarnGB. simq prune [--days 7] [--derived-days 14] [--dry-run] cleans up.
A config change had no effectRestart the agents after editing: run scripts/install.sh again.
