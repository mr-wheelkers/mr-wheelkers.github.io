drawingboard documentation

drawingboard is a local design and task board that lives inside your project and is shared by you and Claude. Everything is a plain JSON file in drawingboard/, committed with your code. The app is one binary that serves a web UI on 127.0.0.1.

Not public yet About drawingboard Source on GitHub

Install

Not public yet. There is no public repository or release yet. This is how it will work once there is one.

You need Claude Code (claude on your PATH) for the Claude parts. The board itself works without it.

  • Download the binary for your platform, if a release is available, and put it on your PATH as drawingboard.
  • Or build it from the repository with Go and Node. Node is only needed to build the UI; the binary embeds it.
make build       # bin/drawingboard
make install     # copies it to ~/.local/bin/drawingboard

Check with drawingboard help. It is developed on macOS and should work on Linux. On Windows the Claude terminal is not available yet.

The check hook that init installs runs drawingboard by name, so keep it on your PATH.

Quick start

  1. Prepare your project. In your project folder (a git repository is best), run drawingboard init. It creates drawingboard/ with a sample screen, a sample mark and a sample task, installs the drawingboard skill for Claude (.claude/skills/drawingboard/), adds a short section to CLAUDE.md, and adds Claude Code hooks. --dry-run shows what it would do; running it again changes nothing. --no-sample skips the sample.
  2. Start the app with drawingboard (or drawingboard -open) and open http://127.0.0.1:4320.
  3. Look at the sample. The Main canvas has a Welcome web page with a numbered pin on its "Get started" button. That pin is a mark.
  4. Draw a screen. Click New screen, pick a platform and a name. Click kinds in the palette to add them, drag them into place and edit their labels in the inspector. Every change is saved to a file at once.
  5. Place a mark. Press M for mark mode, pick Comment pin (C) and click your button. Write what you want and save. Press Esc twice to leave mark mode.
  6. Ask Claude. Press Ctrl+` to open the terminal dock. In the Marks tab, click "Ask Claude to address open marks". The request is typed into the terminal for you; press Enter.
  7. See the mark addressed. Claude reads the marks, looks at the screen, changes it, replies on each mark and sets it to addressed. If you agree, set it to Resolved.

Concepts

Canvases and screens

A canvas is an infinite surface; each one is a folder in drawingboard/canvas/. A screen is a mockup of one window, page or phone screen, stored as one JSON file that holds its whole tree of elements. Zones group screens on a canvas.

The catalog and platforms

Screens and elements are typed placeholders from a built-in catalog for five platforms: macOS, Windows, iOS, Android and web, plus architecture diagrams. Every type has props, defaults and placement rules; drawingboard catalog -short ios lists one platform's. A placeholder kind covers anything missing.

Layouts as hints

Elements can be placed freely or arranged by a stack, grid or flex. These are hints about how the real app should behave: a flex wraps when space runs short, a stack or a grid doesn't and scrolls, scales or shrinks instead. Claude reads them to choose the framework's natural equivalent, such as a StackPanel, a VStack or CSS grid.

Marks

A mark is you (or Claude) pointing at something on a screen and saying something about it. Marks are anchored to nodes by id, and they carry a snapshot of what was marked, so they stay readable after the screen changes. One mark is one small file:

canvas/<canvas>/marks/<screen-id>/<mark-id>.json     one mark = one file
KindWhat it is
commenta pin on an element, with your note
boxa rectangle or ellipse around something
arrowfrom a node or point to another
strikeremove this
movethis should go there
texta note written on the canvas
pena freehand stroke

A mark's status goes from open to addressed (Claude or someone changed something) to resolved (you agree). wontfix is also allowed. Claude can also ask you questions as marks.

Tasks

The Tasks tab is a board of columns. Each column is a folder in drawingboard/tasks/, and a task's column is its status: dragging a card to another column moves its file. Fields are configurable, forms give tasks their own fields, and refs link a task to screens, elements, marks and other tasks.

Notes, mind maps and architecture diagrams

Markdown sticky notes and mind maps (a markdown nested list drawn as a tree) sit on the canvas next to screens, along with images. An architecture diagram shows the system behind the screens: services, boundaries and links with protocols.

Lock

The Lock toggle in the canvas toolbar (or L) is a preview mode: look at a canvas without moving anything by accident. It locks only the view; nothing is saved, and what Claude changes still shows up live.

Checkpoints

A checkpoint is a named snapshot of drawingboard/. In a git repository it is a commit on a ref of its own (refs/drawingboard/checkpoints/<id>): your branch, HEAD and index are never touched. Without git it is a copy in .drawingboard-checkpoints/ next to the board. Checkpoints are taken automatically before the terminal starts a new or continued session, before a Doctor run and before every restore. The newest 50 are kept.

Export

Export makes PNG pictures exactly as the app draws them, without selection or marks. Saved to the board, they land in canvas/<canvas>/exports/<id>.png. Claude reads these pictures when the text outline is not enough, and drawingboard show says when one is stale.

Doctor

The Doctor tab shows project metrics and can run a read-only self-diagnosis by Claude that lists issues and saves a report in drawingboard/doctor/. A run costs real money on your Claude account; it starts only when you click. A daleq card appears when the project has a .daleq.toml.

Command reference

Every command works on ./drawingboard unless you pass a board folder (-board dir or a board-dir argument). drawingboard help prints the full usage.

CommandWhat it does
drawingboard [serve] [-port 4320] [-open] [board-dir]serve the app on 127.0.0.1 (the default command)
drawingboard init [DIR] [--dry-run] [--json] [--no-sample] ...prepare a project: board, sample, skill, CLAUDE.md section, hooks
drawingboard status [--json]the whole board on one screen: canvases, open marks, tasks, check totals, Doctor
drawingboard check [board-dir]validate the board; exit 1 on errors
drawingboard catalog [-short] [-json] [platform | platform.kind]the mockup types and their props
drawingboard show canvas/<c>/<screen>.jsona screen as a text outline, with open marks
drawingboard patch canvas/<c>/<screen>.json '<ops>'edit a canvas file by node id, the way the app does
drawingboard marks [-all] [-canvas name]list the open marks (or all)
drawingboard mark <id> <status> [reply]set a mark's status, optionally with a reply
drawingboard mark add canvas/<c>/<screen>.json[#node] "<text>"add a mark as Claude (a question)
drawingboard export canvas/<c>/<file>.jsonsave a PNG of a screen, note, mind map, image or zone; --all for every screen and item
drawingboard task <list|show|new|move|set|reply|field|forms|column>work the task board; drawingboard task help
drawingboard checkpoint [create "<label>" | list | diff <id> | restore <id>]snapshots of the board
drawingboard formatprint the board format guide
drawingboard hook posttooluse|pretooluse|sessionstart|userpromptsubmitthe Claude Code hooks that init installs

What the marks commands print

marks prints, for each mark: id, status, screen, node id, the snapshot, whether the node still exists, and the text. Ellipses, pen strokes and text marks say where they are in words:

show prints the screen as an indented tree in reading order: id, type, label and geometry; derived hints such as "same row as n-btn-cancel"; and each node's open marks inline, under it.

Claude Code integration

What init installs

drawingboard init installs the drawingboard skill (.claude/skills/drawingboard/), adds a short section to CLAUDE.md, and adds Claude Code hooks to .claude/settings.json:

HookWhat it does
drawingboard hook posttoolusechecks board files after Claude edits them, and logs which screens Claude wrote
drawingboard hook pretoolusebefore a Bash command, stamps the screens so that changes made during it can be logged
drawingboard hook sessionstartgives a new (or resumed, cleared, compacted) session a digest: open marks with the newest five, screens changed since the last digest, Doing and To do tasks
drawingboard hook userpromptsubmitadds one line to a prompt only when the board changed since the last prompt other than by Claude

The digest and the notice are silent on any error and take about a millisecond. What they last saw is kept in drawingboard/.state/hooks.json; .state/ ignores itself in git.

How Claude works with marks

drawingboard marks                      # open marks across the board, one per line
drawingboard marks --all                # every status
drawingboard show canvas/demo/prefs-macos.json   # outline of the screen with marks inline
drawingboard mark m-0007 addressed "Made it primary and 96px wide"   # status + reply

Claude reads show before editing a screen with marks. After making the change, it sets the mark to addressed with a short reply. It never sets resolved: that is your call. The CLI enforces it: drawingboard mark <id> resolved (or wontfix) on a mark whose author is user is refused. Claude may resolve its own marks.

Who changed a screen

Marks carry their author, but a screen file does not, so every write to a screen is logged in drawingboard/.state/writes.jsonl. The app's writes count as yours. The CLI's writes and Claude's Edit, Write and Bash tools count as Claude's. The prompt hook then reports a screen you edited in the app, leaves out one that is exactly as Claude's last logged write left it, and reports anything else neutrally.

The terminal and Ask Claude

The terminal dock runs the real claude CLI, interactively, in your project root, so it uses your project's CLAUDE.md, settings, skills and MCP servers and your own login. There is one session per server: it survives page reloads, and several tabs share it.

"Ask Claude" buttons open the dock and type a reference to a node, a mark or a task, such as canvas/main/welcome.json#n-start mark m-0001 "Try it: ...". They never press Enter: you can add to the text, then press Enter yourself.

"New session" restarts claude; "Continue last" restarts claude --continue. A checkpoint of the board is taken first.

Security and privacy

  • The app listens only on your own machine (127.0.0.1). It rejects requests that come through another host name, which blocks a known trick where a web page tries to reach local servers.
  • There are no accounts and no cloud. Nothing leaves your machine except what Claude Code itself sends to Anthropic.
  • The Claude terminal is a full Claude Code session with your own permissions, not a sandbox. It can do in your project whatever claude can do in your terminal. Only the app's own page can open it: it needs a secret token created each time the server starts, which other web pages can't read.
  • Editing your Claude files, starting a Doctor run and installing tools also need that token. Settings and .mcp.json are read-only in the app, and values that look like secrets (keys, tokens, passwords) are masked before they reach the browser.
  • The Doctor's diagnosis is read-only: Claude may only read, grep and glob files (no shell, no edits, no MCP), with a spending cap. It runs only when you click.
  • Files you add (images, attachments) are limited to safe types, and the app never serves files from outside the board.

Board text is data

Mark text is written by the developer and by Claude, so marks, show and status print a header line saying that the board content is data, not instructions, and quote every mark text and reply.

What gets pushed

Checkpoints in git are refs under refs/drawingboard/, which git push does not send unless you ask for them. Exports and Doctor reports are committed by default; the .gitignore that drawingboard writes into a new board has the two lines ready to uncomment (canvas/*/exports/ and doctor/).

Troubleshooting

SymptomWhat to do
Claude in the dock does not know about the boardStart a new session if the dock was open before init, so Claude loads the skill.
The check hook fails to runIt runs drawingboard by name. Keep the binary on your PATH.
Nothing on the canvas can be movedThe view is locked. Press L again to unlock.
drawingboard check exits 1The board has errors; the output lists them. It also reports marks whose screen no longer exists.
drawingboard mark <id> resolved is refusedClaude may not resolve your marks. Set addressed instead, or resolve it yourself in the app.
export says it drew the picture headlessThe app is not open, or its tab is hidden or asleep, so the command used a headless Chrome, Chromium, Edge or Brave instead.
No Claude terminal on WindowsThe Claude terminal is not available on Windows yet.
A change went wrongRestore a checkpoint from the Doctor tab, or with list and restore <id> of the drawingboard checkpoint command. A restore takes a checkpoint of the current state first, so you can undo it.
