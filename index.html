Five local tools for working with Claude Code

A job daemon, a design board, a picture review page, a Godot harness and an iOS test queue. Each runs on your own machine and keeps its state in plain files you can read.

See the tools Documentation

The tools

  • daleq

    A small local daemon that runs an agent's long commands for it: builds, test suites, dev servers.

    It hands back a job id at once, runs the command under watchdogs, and keeps every output and outcome on disk. A build started before a rate-limit pause still has its result afterwards, and the same command on an unchanged tree is not run twice.

    Not public yet About daleq Documentation Source on GitHub

  • drawingboard

    A design and task board that lives inside your project and is shared by you and Claude.

    When you circle a button and write "too small, make it primary", that is saved as data on the button's id, not as pixels. Claude reads the mark without a screenshot, changes the screen and sets the mark to addressed. Only you resolve it.

    Not public yet About drawingboard Documentation Source on GitHub

  • imgcompare

    A local review page and a CLI for comparing pictures: art directions, mockups, screenshots, icons.

    You draw Like and Don't like marks on any image, vote, pick the designs you prefer and say what to take from each. It steps animations frame by frame, so a note can sit on one frame. Claude reads it all back as Markdown or JSON.

    Not public yet About imgcompare Documentation Source on GitHub

  • godot-pilot

    A test and debug harness that lets Claude drive a Godot .NET game and the Godot editor.

    Runs are deterministic: the game advances only when stepped, with a fixed timestep, a seeded RNG and an injectable clock. Scenarios print failures only, and a release gate proves that none of the harness ships in an exported build. macOS and C# only. Jev (TypeSafe AI) is an optional, paid extra for visual checks.

    Not public yet About godot-pilot Documentation Source on GitHub

  • simq

    A queue for iOS simulator tests.

    Any number of sessions submit a test run. An always-on harness runs them one per simulator, with warm DerivedData, and skips the build when the source has not changed. It is being folded into daleq's iOS plugin, which reads the same .simq.toml.

    Not public yet About simq Documentation Source on GitHub

How they fit together

Two of the tools are places where you and Claude look at the same thing. Three are ways for Claude to run something without getting stuck on it.

  • daleq runs the long jobs. Anything that may take more than a minute, never ends on its own, or only waits goes through it, so no session hangs on a process.
  • drawingboard is the shared board. You sketch screens and keep tasks; Claude reads and edits the same files. When a project has a .daleq.toml, the board's Doctor tab shows a daleq card.
  • imgcompare is picture review. When Claude has made several pictures, it serves them for you to mark and pick, then reads your feedback as the brief for the next round.
  • godot-pilot is the Godot test and debug harness: input, frame stepping, screenshots, state and live C# eval, for the game and the editor.
  • simq is the iOS simulator test queue. It is being folded into daleq: daleq's iOS plugin reads simq's .simq.toml, and its simulators keep the simq- names.

None of them needs the others. Install the one whose problem you have.

What they share

  • They run on your machine. The board and the review page are served on 127.0.0.1. The daemons answer on a Unix socket, and the Godot harness on localhost with a per-session token.
  • State is plain files. A daleq job is a folder with output.log in it. A mark is one JSON file. A review is manifest.json and feedback.json. You can read all of it without the tool.
  • A project adopts a tool with one command. daleq init, drawingboard init, imgcompare init and pilot init each prepare a project, can be run again safely, and take --dry-run.
  • Claude is taught, not left to guess. daleq, drawingboard, imgcompare and simq each bring a skill; daleq, drawingboard and imgcompare add hooks. godot-pilot is a CLI whose output is written for an agent.
  • Little leaves the machine. daleq has no telemetry and makes no network connections, except between machines you join into a cluster yourself. drawingboard has no accounts and no cloud. godot-pilot sends only screenshots of seeded game content to Jev, and only when Jev is enabled.
